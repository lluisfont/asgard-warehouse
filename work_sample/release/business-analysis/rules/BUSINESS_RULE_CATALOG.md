# Business rule catalog

Estado: candidate_reconstruction  
Confianza: media

| Regla transversal | Descripcion candidata |
|---|---|
| Segmentacion por cliente | Datos, reportes, documentos y permisos se filtran por cliente/tenant |
| Estado gobierna acciones | Transiciones de caso/documento/factura habilitan o bloquean operaciones |
| Documento requerido | Algunos hitos no avanzan sin soporte documental |
| Validacion por catalogo | Puertos, carga, mercancia, agentes, tipos y parametros condicionan formularios |
| Variante por cliente | Clientes especificos tienen OCR, reportes, reglas o pantallas particulares |
| Auditoria de acceso | Login, historial y eventos relevantes deben trazarse |
| Generacion documental | Planillas, facturas y reportes deben preservar formato historico |
| Integracion externa | Fallos de correo/OCR/SFTP/API requieren manejo operacional |

## Fuente

Consolidado desde 70 dominios candidatos, catalogos tecnicos, schema y evidencias Graphify/PHP.
